# ARCHITECTURE.md — decision record

The full design is [PHASE1_ARCHITECTURE.md](PHASE1_ARCHITECTURE.md) (v1.0, single source of
truth). This file records the locked decisions plus anything T0+ implementation added or
resolved. New event types and any divergence from the design doc must be noted here.

## Locked decisions (from PHASE1_ARCHITECTURE.md §1)

- **D1 — Event-sourced session log.** `interview_events` is append-only and the single source
  of truth; transcripts, editor deltas, hints, executions, state transitions are all events.
- **D2 — Dual-model split.** Haiku-class conduct model live; Opus-class evaluation model async.
  The conduct model never produces scores.
- **D3 — State machine owns the interview.** Transitions are code (time budgets + completion
  criteria); the LLM only controls behavior within a state.
- **D4 — Streaming + pipelining everywhere.** STT interims → LLM token stream →
  sentence-chunked TTS; no stage waits for the previous one.
- **D5 — Prompt caching on every conduct call.** Cache-stable A/B/C/D context layout (§6.3).
- **D6 — Deterministic signals in Python, judgment in the LLM.**
- **D7 — Every LLM call carries a `prompt_version_id`.**

## T0 implementation decisions (2026-08-23)

| Decision | Detail |
|---|---|
| Model IDs | Verified against live Anthropic docs at T0: conduct = `claude-haiku-4-5` ($1/$5 per MTok, 200K context), eval = `claude-opus-5` ($5/$25 per MTok, 1M context). Recorded in `.env.example` and `backend/providers/pricing.py`. Re-verify before any model swap. |
| Event immutability enforcement | Enforced at the **database level**: a `BEFORE UPDATE` trigger on `interview_events` raises. DELETE is left open solely for the T9 retention purge job; application code never deletes (code-review discipline + tests). |
| Closed event vocabulary | Validated app-side (`EVENT_TYPES` in `backend/app/models.py`, enforced by the `POST /sessions/{id}/events` schema). The DB column stays `text` so extending the vocabulary is a code change + migration note here, not a type migration. |
| Monotonic seq | `(session_id, seq)` unique constraint + endpoint check that a batch's seqs are unique and strictly greater than the session's current max; races 409/conflict rather than corrupt. |
| Provider abstraction | `backend/providers/base.py`: requests are built from `ContextBlock`s so the **caller** controls cache breakpoints (the engine's §6.3 layout maps 1:1 onto blocks). Providers stay swappable; `AnthropicProvider` is the Phase 1 default (async, streaming with TTFT measurement, cache_control on marked blocks). |
| OpenRouter provider | `LLM_PROVIDER=openrouter` + `OPENROUTER_API_KEY` switches all LLM calls to OpenRouter's OpenAI-compatible endpoint (model names become OpenRouter slugs, e.g. `anthropic/claude-haiku-4.5`). Cache breakpoints pass through to Anthropic-family models; OpenRouter's reported `usage.cost` is captured on `LLMResult.cost_usd` and preferred over the local estimate when present. Latency note: OpenRouter adds a routing hop — first-party Anthropic remains the default for the voice path; re-measure T1 targets before conducting real interviews through OpenRouter. |
| llm_calls logging | The provider returns an `LLMResult` with token/cache/latency fields; persisting to `llm_calls` with a `prompt_version_id` is the caller's obligation (wired in T2 for conduct, T6 for eval). `providers/pricing.py` computes the cost estimate. |
| Compose profiles | Default `docker compose up` brings up the T0-required set: postgres, redis, minio (+bucket init), api, eval-worker. Deferred services are profile-gated: `--profile editor` (y-websocket, T3), `--profile sandbox` (Judge0, T4 — see infra/judge0/README.md), `--profile frontend` (containerized Next dev server; local `npm run dev` works too). The agent worker (T1) is run locally during the spike and containerized when it stabilizes. |
| Migrations | Forward-only: `downgrade()` raises. Hand-written (not autogenerated) for determinism. |
| Python | 3.11+ target (`requires-python >= 3.11`), containers run 3.12-slim. |
| Judge0 on Windows dev | Pinned judge0/judge0:1.13.1 (cgroup-v2 compatible); runs under the `sandbox` compose profile with its own postgres+redis. Verified working on this dev machine (steady-state ~0.3–1.4s per submission; first submission after cold start ~8s). |
| Execution service (T4) | Backend-only path to Judge0 via `POST /execute` (session-scoped, Redis lock enforces one concurrent execution per session, 60s TTL). Sync submissions (`wait=true`). Statuses mapped to: accepted, wrong_answer, time_limit_exceeded, memory_limit_exceeded, runtime_error, compile_error. Hidden-test shaping in `app/execution.py::shape_response` — hidden cases expose pass/fail/time only; contract-tested in `tests/test_execution.py`. Full results (incl. hidden detail) go to the event log via server-side `append_event`, which allocates seq with retry — mixed client/server writers contend on (session_id, seq) and resolve via the unique constraint. |

## T2/T3 implementation decisions (2026-08-23, cont.)

| Decision | Detail |
|---|---|
| Server-assigned event seq | With three writers (agent worker, browser beacons, server-side appends), client-assigned seq collides. `POST /events` now assigns seq under a per-session Postgres advisory lock (`pg_advisory_xact_lock(hashtext(session_id))`), preserving batch order. Client-supplied seq is ignored. |
| Prompt versioning flow | Files in `/prompts/<role>/<name>_vN.txt` are the source; `backend/scripts/sync_prompts.py` mirrors them into `prompt_versions` (new row on any content change — audit trail preserved). `POST /llm-calls` resolves `prompt_version_name` to the newest matching row and rejects unknown names. |
| Backend-decided questions | Sessions default to the newest interview plan; the plan's `question_refs.coding` picks the question; `GET /sessions/{id}/question` serves statement + visible tests only. All question reads (admin included) expose hidden tests as a count — expected outputs never leave the DB via any endpoint. |
| Editor durability model | Yjs/y-websocket doc is the live truth but in-memory only; the event log is durable. On (re)join with an empty shared doc, the client restores from `GET /sessions/{id}/code_at?ts=now`. Empty periodic snapshots are skipped (deltas already record deletions; an empty snapshot would bury the last meaningful base). |
| Conduct prompt structure | `base_v1` (persona + @meta output contract + spoken-style + candidate-wellbeing/distress rule) + per-state goal files (intro/warmup/technical_deepdive/coding/wrapup). The distress rule (acknowledge, offer to pause, never steer back unprompted) is a hard requirement from live testing. |
| Pinned frontend deps | monaco-editor pinned 0.52.2 (0.53+ exports map breaks y-monaco's deep import); y-websocket server pinned v1 (`npx y-websocket@1`) — v2 dropped the bundled server binary. |
| Agent deps | livekit-plugins-anthropic requires `anthropic<1` (1.0 switched to httpx2). ElevenLabs plugin reads `ELEVEN_API_KEY`; we pass `api_key=` explicitly from `ELEVENLABS_API_KEY`. Local dev uses VAD interruption + local `EnglishModel` turn detector (LiveKit-Cloud-hosted variants 401 against a local server). Preemptive generation enabled (§2.2 technique 10). |

## Rounds / T6 / T7 decisions (2026-08-23, cont.)

| Decision | Detail |
|---|---|
| Plan-driven rounds | A plan defines `rounds: [{id, type, minutes, question?}]`; the engine walks them in order. Round types: intro, warmup, discussion, coding, sql (+ reserved quiz/artifact). Code rounds (`coding`,`sql`) bind a question, enable the observation loop, and carry per-round post-solution completion criteria. Legacy §6.2 plans are synthesized into the classic five-round sequence with their original state names as round ids, so old event logs rebuild unchanged. `state_transition.to` now carries a round id; `ENDED` is the virtual terminal. |
| SQL round | Judge0 language 82 (SQLite). Test cases carry `setup_sql` (schema+data) prepended server-side to the candidate query per case, so hidden cases vary the dataset. Same hidden-test shaping as coding. |
| Deviation from §9 layout | The eval pipeline lives in `backend/app/eval/` (signals, pipeline, brief, worker), not `/worker` — the worker container runs the backend image (`python -m app.eval.worker`) so it shares `providers/` and the models, keeping invariant #2 without duplicating code. `/worker` dir is retired. |
| T6 two-pass eval | Pass 0 deterministic signals (unit-tested). Pass 1 evidence extraction, pass 2 scoring from evidence only — both via providers/ with `evaluate/evidence_v1` / `evaluate/scoring_v1` prompt versions logged to llm_calls. Validation: pydantic schema + citation resolution against real event ids; one retry, then stored `degraded` for human attention. Re-runs create version+1 (verified: v2 alongside untouched v1). Trigger: PATCH status→completed LPUSHes `evaluate_session` (fire-and-forget). |
| T7 brief — deterministic assembly | Phase 1 assembles the recruiter layer in code from the evaluation itself (top/bottom competencies + their cited evidence, uncertainty statements, neutral integrity notes), so "every recruiter claim traces to an audit citation" is true by construction — no brief-generation LLM call yet (the §8 brief prompt slot stays open for prose polish later). Hire signal = weighted rubric vs role-config thresholds, computed in code. Self-contained HTML stored in MinIO `briefs` bucket; served via `GET /sessions/{id}/brief.html` + JSON at `/brief`. |

## T5 / T8 / T9 decisions (2026-08-23, cont.)

| Decision | Detail |
|---|---|
| Graduated hints (T5) | Hint texts reach only the agent worker via `GET /sessions/{id}/questions?include_hints=1` (never the candidate UI). Escalation is engine-gated (`authorized_hint_level`): level N+1 only ≥90s after level N AND tests still failing; only the authorized level's content enters the model context; issuance folds a `hint_issued` event `{round_id, level}`. |
| Twist + think-aloud (T5) | `should_fire_twist`: visible tests pass with ≥40% round budget remaining, once per round (`twists_fired` per-round in EngineState). `should_nudge`: >90s candidate silence while editing, max 2/round (nudges folded from agent_turn `nudge` flag). Both pure + unit-tested. |
| Provider failover (T9) | LiveKit `FallbackAdapter` wraps TTS (ElevenLabs↔Cartesia) and LLM (Anthropic↔OpenRouter) whenever both providers have keys; session `error` events land in the log. STT reconnect is framework-native. Recording via LiveKit egress is **deferred** — needs egress+redis infra locally or LiveKit Cloud; noted as the remaining T9 gap. |
| Latency dashboard (T9) | `GET /metrics/latency` aggregates `turn_latency` events per session (p50/p95 + stage medians + recent-turn sparkline data); `GET /metrics/llm-calls` aggregates cost/tokens/TTFT per role+model. UI at `/admin/latency`, auto-refreshing. |
| Retention purge (T9) | `scripts/purge_retention.py [--dry-run]` — the sole sanctioned deleter of `interview_events`; also removes MinIO recordings past `retention_days`. Evaluations/briefs are kept (durable outcome). Run nightly via external scheduler. |
| Shadow mode (T8) | Blind review UI at `/admin/review/[id]` (AI scores fetched only after submission); `human_evaluations` stores the same rubric shape. `GET /calibration(.html)`: per-competency Spearman (tie-safe, hand-verified), mean abs diff, |Δ|≥2 disagreement queue, pass/fail agreement at role-config hire threshold. n<20 → prominent "insufficient data" warning and no headline correlation. |

## Phase 2 / T10 decisions (2026-08-23)

| Decision | Detail |
|---|---|
| Auth seam | Org users authenticate via a pluggable resolver (`app/tenancy.py::get_org_context`): candidate JWT → internal service key → dev IdP stub (X-Org-Id/X-Role/X-User-Email headers) → dev default-org fallback. Clerk/Auth0 replaces the header stub only; nothing else changes. `DEV_DEFAULT_ORG` must be false in production. |
| RLS binding | Superusers bypass RLS unconditionally — the Postgres image's bootstrap user is a superuser, so the app connects as non-superuser `app_user` (NOSUPERUSER NOBYPASSRLS, migration 0006); migrations run as the owner via `MIGRATIONS_DATABASE_URL`. Policies deny-by-default (unset `app.current_org` = zero rows) and are FORCEd. |
| Bypass channel | `app.bypass_rls='on'` GUC is the worker/maintenance channel (eval worker locates a session, then pins its org per invariant #8; purge job). Honest note: a GUC is application discipline, not a defense against SQL injection — production hardening (T18) should split worker/admin into separate DB roles. |
| org_id backfill on interview_events | Required temporarily disabling the append-only trigger inside migration 0005 — schema migration is the sole sanctioned context. |
| prompt_versions stays global | The prompt library is platform-level (shared across orgs); org-custom prompts would add org_id + RLS in their own migration. |
| Candidate links | JWT (HS256, `CANDIDATE_LINK_SECRET`), 24h TTL, single-session scope enforced app-side on top of RLS, revocable via `sessions.candidate_jti` rotation; minting is audit-logged. Candidates can never read hints (`include_hints` 403s for candidate role). |
| Cross-tenant suite | `backend/scripts/test_tenancy.py` — CI-blocking per invariant #8: read+write isolation across every surface, role gates, candidate scope, audit trail, dev fallback. |

Restore a real load_fnc only alongside scale-out |
| Workflow frontend | F0-F9 build on Tailwind tokens ("instrument" direction, frontend/DESIGN.md): candidate /i/[token] flow + org surface (/dashboard ... /settings); legacy pages remain during migration; deltas in frontend/DEVIATIONS.md | Spec: PLATFORM_WORKFLOW_SCREENS.md; the section-7 status matrix is implemented once in lib/visibility.ts |
| Read-endpoint auth | Scores/briefs/metrics/listings all require reviewer+ (or service key); gated HTML documents are fetched with auth and rendered via srcDoc | Anonymous reads of candidate data were an audit finding; DEV_DEFAULT_ORG=false enforces login in this deployment |

| Production posture | ENVIRONMENT=production refuses to boot with dev-default secrets, disables the X-Org-Id dev auth stub and on-screen OTPs; CORS origins from env; startup check in app/main.py::validate_production_posture | Dev conveniences must be impossible to ship by accident, not merely documented |
